How this works: Every generated timetable is checked against {{ report.constraint_summary.hard_rule_count }} hard constraints (must always pass - if even one couldn't be satisfied, generation fails outright rather than produce a broken schedule) and {{ report.constraint_summary.soft_rule_count }} soft constraints (weighted trade-offs the solver balances against each other while searching for the best schedule it can find). Because a completed schedule can never actually violate a hard constraint, those aren't scored - they're shown below as a pass/fail checklist instead. The Optimised Score above is built entirely from the soft constraints: each violation costs points equal to that rule's own priority - the same weight the solver itself uses internally to decide which trade-offs to make when it can't honour every soft preference at once, so "ends late" (priority 15) costs far more than "not the snuggest room fit" (priority 2). Those weighted points are averaged across every session, then scaled so an average of {{ report.score.ceiling }} points per session brings the score to 0 - a higher priority rule being broken pulls the score down faster than a low-priority one.
